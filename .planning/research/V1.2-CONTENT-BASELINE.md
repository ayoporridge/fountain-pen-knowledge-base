# v1.2 品牌与型号内容基线审计

> 审计日期：2026-07-15  
> 数据快照：`data/fpkg.db`  
> 审计范围：全部公开 `brand` 与 `pen`，非抽样  
> 公开规则：严格应用 `src/lib/public-visibility.ts`  
> 审计性质：只读；本报告生成期间未修改代码或数据库

## 1. 结论

当前站点并不是“数据库没有内容”，而是同时存在三类问题：

1. 数据库里的文字被详情页渲染规则主动隐藏；
2. story、spec、claim、media、timeline 等记录虽存在，但审核状态或公开条件不合格；
3. 旧审计只检查“有没有记录”，没有检查“用户实际上能不能看到”。

公开规则下共有 296 个品牌/型号页面：65 个品牌、231 个型号。其真实公开内容情况如下：

| 指标 | 品牌 | 型号 | 合计 |
|---|---:|---:|---:|
| 公开条目 | 65 | 231 | 296 |
| 有可见叙述正文 | 0 | 53 | 53 |
| 无可见叙述正文 | 65 | 178 | 243 |
| 有可见规格 | 0 | 9 | 9 |
| 有可见来源 | 50 | 190 | 240 |
| 有公开图片 | 60 | 8 | 68 |
| 有可见时间线 | 2 | 0 | 2 |

没有任何一个型号同时具备“可见正文＋可见规格”。也没有任何一个型号同时满足“正文、规格、来源、图片”四项完整标准。

当前仅有的 53 个可见型号正文全部来自 Richard’s Pens 同一个历史资料批次，内容结构严重偏向欧美老笔。现代常见型号页大多只剩标题、标签、关系、空状态说明或来源链接。

## 2. 审计口径

### 2.1 公开实体

数据库中共有 69 个 brand、236 个 pen。按公开规则排除 4 个隐藏品牌和 5 个隐藏/重复型号后，得到：

- 公开品牌：65
- 公开型号：231
- 合计：296

对 brand/pen 而言，当前公开规则仅检查 slug 是否在隐藏名单中，没有内容完整度门槛。只要不在黑名单中，即使没有任何可见正文、规格、图片或来源，仍会公开。

### 2.2 “可见”定义

本报告不把数据库中“存在一行记录”视为内容完成，而是按当前前台实际读取条件判断：

- 叙述正文：当前详情页真正渲染的正文；
- spec：`model_specs.review_status = 'approved'`，且存在指向 approved source 的有效 citation；
- reference：`entity_references.review_status = 'approved'` 且 `source_items.review_status = 'approved'`；
- media：完整通过 `publicMediaFilter`；
- timeline：品牌页实际读取到的 approved event＋approved source；型号页当前不渲染 timeline；
- story：只有详情页实际调用并允许的 story 才视为可见。

### 3.2 Entity body

| 类型 | 空 | 1–299 字 | 300–1199 字 | ≥1200 字 | 平均 | 最短 | 最长 |
|---|---:|---:|---:|---:|---:|---:|---:|
| brand | 64 | 1 | 0 | 0 | 2.0 | 0 | 130 |
| pen | 0 | 177 | 1 | 53 | 1497.3 | 96 | 19657 |

品牌 body 无论是否存在都不会在品牌详情页渲染。唯一有 body 的品牌是 Pilot，130 字，同样不可见。

型号 body 只有同时满足以下条件才会显示：

1. `source_url` 是有效 HTTP(S) URL；
2. 不是 Bing 搜索占位 URL；
3. body 长度至少 1200 字。

因此只有 53 个型号显示 entity body；其余 178 个型号 body 全部不可见。

特殊边界条目：

- `上海-shanghai-97回归` 的 body 为 475 字，并且有英雄官网来源，但仍因 1200 字门槛不显示；
- 53 个可见长正文全部来自 `richardspens.com`，长度 1891–19657 字，平均 5912.8 字。

## 13. 旧审计假阳性

### 13.1 `scripts/audit-entity-quality.ts`

实际运行结果：

```json
{
  "entities": 582,
  "duplicateGroups": 0,
  "suspiciousPenArticles": 0,
  "thinEntities": 0,
  "brokenLinks": 0
}
```

假阳性/假阴性原因：

1. 查询全部 582 个实体，没有应用 `publicEntityFilter`；
2. `story_count` 统计所有状态，deprecated 也算故事；
3. `claim_count` 统计所有状态，pending/needs_source 也算事实；
4. `bodyLength < 80` 只有在 `story_count === 0` 时才报错；当前每条都有一篇 deprecated story，因此永远绕过；
5. 只有 `claim_count === 0` 才报错；当前每条至少有一条未审核 claim，因此永远绕过；
6. 最后还要求至少命中两个 reason 才进入 `thinEntities`；
7. 不检查 summary/body 是否在前台实际渲染。

因此即使 64 个品牌 body 为空、296 条 story 全部 deprecated、283 条没有 approved claim，脚本仍报告 `thinEntities: 0`。

### 13.2 `scripts/audit-library-coverage.ts`

实际运行结果：

- 69/69 个品牌 ready，平均 96 分；
- 233/236 个型号 ready，平均 80 分；
- 统计包含 9 个实际已隐藏实体。

假阳性逻辑：

1. 没有应用公开规则；
2. stories、claims、references、media、timeline、diagram、spec 都只数行数；
3. deprecated story 获得 2 分；
4. pending/needs_source claim 获得 2 分；
5. pending/needs_source spec 获得 2 分；
6. pending reference 或未审核 source 仍计为来源；
7. 不可复用、remote-only、candidate、hidden media 仍计为媒体；
8. pending/needs_source timeline 仍计为时间线；
9. draft diagram 仍计为图示；
10. 完全不检查 summary/body 是否渲染。

如果沿用相同权重，但把每一项替换为“当前前台实际可见且证据有效”：

| 类型 | 总量 | 平均分 | ready | starter | gap | 最低 | 最高 |
|---|---:|---:|---:|---:|---:|---:|---:|
| brand | 65 | 39.1 | 0 | 2 | 63 | 11 | 78 |
| pen | 231 | 14.9 | 0 | 1 | 230 | 0 | 50 |

该修正分数只用于说明旧审计偏差，不应直接作为最终 v1.2 发布标准。

## 14. 逐条机器清单字段契约

后续必须为全部公开 brand/pen 生成逐条 NDJSON 或 CSV，不允许只输出汇总。

建议 JSON Schema 语义：

```json
{
  "id": "string",
  "type": "brand|pen",
  "slug": "string",
  "name": "string",
  "public_url": "string",
  "summary_chars": 0,
  "entity_body_chars": 0,
  "visible_narrative": false,
  "narrative_blocker": "summary_hidden|body_empty|body_too_short|missing_source_url|placeholder_source_url|none",
  "story_total": 0,
  "story_public": 0,
  "story_deprecated": 0,
  "story_chars": 0,
  "story_types": [],
  "story_statuses": [],
  "spec_status": "approved|pending|needs_source|rejected|none",
  "spec_filled_fields": 0,
  "spec_citations": 0,
  "spec_valid_citations": 0,
  "spec_visible": false,
  "claims_total": 0,
  "claims_approved": 0,
  "claims_approved_with_source": 0,
  "references_total": 0,
  "references_visible": 0,
  "references_official": 0,
  "references_high_reliability": 0,
  "references_retailer_only": false,
  "media_total": 0,
  "media_nominal_approved": 0,
  "media_public": 0,
  "media_blockers": [],
  "timeline_total": 0,
  "timeline_approved_sourced": 0,
  "timeline_visible": 0,
  "diagrams_total": 0,
  "diagrams_reviewed": 0,
  "diagrams_visible_on_detail": 0,
  "aliases": 0,
  "external_ids": 0,
  "brand_relation_visible": false,
  "representative_model_count": 0,
  "flags": [],
  "repair_priority": "P0|P1|P2",
  "research_status": "not_started|sources_found|drafted|reviewed|published"
}
```

字段规则：

- `visible_narrative` 必须按实际 renderer 契约计算，不能只判断 body 非空；
- `spec_visible` 必须复用 `getModelSpec()` 的审核与 citation 条件；
- `references_visible` 必须同时审核 relation 和 source item，并按 URL 去重；
- `media_public` 必须直接复用 `publicMediaFilter()`；
- `timeline_visible` 要区分 brand/pen 组件是否真正渲染；
- `flags` 可多值；
- `repair_priority` 建议 P0 为 no_core_content/核心热门型号空页，P1 为缺正文或缺规格，P2 为补图、时间线、别名等增强项。

## 15. v1.2 修复时的最低验收原则

本报告只建立基线，不定义最终内容篇幅，但后续验收至少应满足：

1. 发布规则、详情页 renderer、coverage audit 使用同一套可见性契约；
2. 不再把 deprecated/pending/needs_source/draft 记录计为公开完成；
3. 每个公开品牌和型号都有可见、来源可追溯的叙述内容；
4. 型号规格按字段核验，不使用一条 queue anchor 证明整行规格；
5. 图片必须可合法复用、落本地并保留来源与 attribution；
6. 来源不得只依赖 retailer；
7. 新增品牌和型号前先完成身份消歧与 made_by 关系；
8. 逐条机器清单必须覆盖全量公开实体，不能以抽样通过代替全量通过；
9. P0 条目清零后才可宣称“没有空页面”；
10. 最终验收需同时跑数据库 contract、前台全页面遍历和 production live truth 检查。
