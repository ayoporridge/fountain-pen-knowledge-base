# V1.2 Public Entity Publication Contract

> 状态：实施契约  
> 适用范围：品牌与钢笔型号为第一优先级；同一公开边界最终覆盖全部 entity 类型  
> 核心原则：数据库中存在一条记录，不等于它已经达到公开标准

## 1. 目标

V1.2 必须消除公开空壳页，并建立一个能长期约束内容导入、补全、扩充和发布的统一门槛。

发布系统必须保证：普通用户从 sitemap、分类浏览、品牌页、关系图谱、推荐或直接链接进入任意公开钢笔/品牌页时，看到的是一份可读、有图、有关键事实、有明确来源、版本边界清楚的成品，而不是只有标题、关系、标签、来源链接或“暂无内容”的资料壳。

本契约同时约束：

- 公开页必须展示什么。
- summary、story、body、spec、claim、reference、media 分别承担什么职责。
- 哪些审核状态可以计入发布门槛。
- 来源可靠性、来源独立性和使用许可如何处理。
- 现售、vintage、地区版、特别版和来源冲突如何建模。
- sitemap、browse、API、图谱和详情页如何共享同一个公开集合。
- audit、CI 和全量 E2E 如何阻止空壳再次上线。

## 2. 当前根因与基线

### 2.1 Montblanc 149 空壳的直接原因

用户报告的 `万宝龙-montblanc-大班149-meisterst-ck` 在数据库中并非完全没有数据：

- `summary` 为 58 字。
- `body_md` 为 266 字，内容仍是旧 CSV 规格卡。
- 有一篇 2020 字 `model_story`，但状态为 `deprecated`。
- 唯一 claim 为 `pending`。
- model spec 为 `needs_source`。
- 有两条 approved reference。
- 有一张 approved primary 图片。

页面仍然表现为空壳，是因为：

1. 详情页明确不展示 pen/brand 的 summary。
2. 详情页明确不展示 pen/brand 的 `body_md`。
3. 页面没有读取 `model_story` 或 `brand_story`。
4. `ModelArchive` 只显示 `approved` 且具有 approved citation chain 的 model spec。
5. `publicEntityFilter` 对 pen/brand 没有内容门槛；除少量手工黑名单外，一律视为公开。

因此该页只剩标题、图片、两条来源、图谱和“这个型号暂时没有可公开展示的结构化规格”。这是数据发布边界与页面渲染契约不一致造成的系统性问题。

### 2.2 当前全库真实基线

当前数据库共有 236 支钢笔、69 个品牌；现行手工过滤后公开 231 支钢笔、65 个品牌。

| 项目 | 钢笔 | 品牌 |
| --- | ---: | ---: |
| 当前公开 | 231 | 65 |
| 有当前页面可见的长篇来源正文 | 53 | 品牌页不渲染正文 |
| 有公开结构化规格 | 9 | 不适用 |
| 有至少一条公开来源 | 190 | 50 |
| 有公开图片 | 225 | 60 |
| 有公开时间线 | 1 | 2 |
| 有代表型号关系 | 不适用 | 62 |

底层审核状态：

- 313 篇 `brand_story/model_story` 全部为 `deprecated`，没有一篇 `published`。
- 390 条 claims 中只有 14 条 `approved`；249 条 `needs_source`，127 条 `pending`。
- 236 份 model specs 中只有 9 份 `approved`；212 份 `needs_source`，15 份 `pending`。
- 现有覆盖率脚本把 deprecated、pending、needs_source 和 candidate 数据也计入完成度，因而误报 69/69 brands ready、233/236 pens ready。

这些数据不能通过批量改状态来修复。deprecated 内容必须重新核对来源、事实和中文表达，再进入正式审核。

### 2.3 为什么旧的 62/62 仍然通过

旧验收覆盖的是可访问性、结构和技术完整性，没有覆盖内容最低密度：

- 代表性详情测试只检查 LAMY 2000 这一个已经有 approved spec 的样板。
- 现有测试明确接受某个型号没有规格但仍返回公开 200。
- sitemap 全量测试只检查 HTTP 200、H1、内部链接、图片错误、编辑状态词和移动端溢出。
- “HTML 有 H1”被视为不是空 shell；正文、摘要、规格、来源和图片均无最低量断言。
- `sitemap >= 550` 奖励页面数量，没有要求 sitemap 集合等于“内容达标集合”。
- entity quality audit 对 story/claim 不筛状态，而且至少同时出现两个问题才报薄弱。
- library coverage 对 story、claim、reference、media、timeline 和 spec 均未按公开审核状态过滤。

旧的 62/62 对当时写下的断言是真实结果，但断言没有表达“普通用户打开任意页面都能获得足够内容”这一业务目标。

## 3. 不可替代的内容职责

不同数据类型只能在自己的维度计分，不能互相冒充：

| 内容类型 | 唯一职责 | 不得替代 |
| --- | --- | --- |
| `entities.summary` | 分类卡片与详情页首屏摘要 | 正文、规格、证据 |
| `stories.body_md` | 面向用户的站内编辑正文 | 结构化规格、逐项证据 |
| `entities.body_md` | article 正文或待迁移的 legacy/source material | pen/brand 的正式站内正文 |
| `model_specs` | 可比较的结构化型号事实 | 正文、版本说明、体验判断 |
| `claims` | 原子事实与证据绑定 | 面向用户的完整文章 |
| `entity_references` | 证明来源与实体相关，组成参考书目 | 证明某个具体规格正确 |
| `citations` | 将 claim、spec 字段或 story 段落绑定到来源 | 仅以来源数量代替事实审核 |
| `media_assets` | 对应实体的可复用媒体 | 正文、规格、来源 |
| tags、aliases、links、recommendations | 分类、身份辅助和漫游关系 | 任何核心发布门槛 |

summary 如果只是复制正文首句，不额外计分。十个标签、三条关系、一张图片和两条来源链接，也不能把没有正文或规格的页面加分到合格。

## 4. 审核状态统一规则

以下状态才能计入公开门槛：

| 数据 | 唯一有效状态 |
| --- | --- |
| entity publication | `published` |
| model/brand story | `published` |
| claim | `approved` |
| model spec | `approved`，且每个公开字段有 approved citation |
| entity reference | `approved`，且对应 source item 为 `approved` |
| source item | `approved`，并满足 allowed-use 约束 |
| timeline event | `approved`，且来源为 `approved` |
| model variant | `approved`，且来源为 `approved` |
| media | `approved` + `primary/gallery` + 可复用许可 + 对应实体审核通过 |
| content/language review | `approved`，且绑定当前 content hash |

以下状态全部计零，不得通过数量或总分补偿：

`reviewed`、`pending`、`needs_source`、`needs_review`、`needs_license`、`candidate`、`draft`、`deprecated`、`rejected`、`hidden`。

其中 `reviewed` 仅表示已进入审核流程；面向公众仍须显式 `published`。

## 5. 普通用户必须看到的内容

### 5.1 钢笔型号页硬门槛

每个公开型号页必须同时满足：

1. **身份明确**
   - 有 canonical name、slug、品牌关系。
   - 常见中文名、英文名、型号编号以 aliases 表达。
   - 不存在未解决的重复实体或类型歧义。
2. **自然中文摘要**
   - 60–160 个中文可见字符。
   - 能独立说明“这是什么、最值得注意的是什么”。
   - 不含编辑提示、研究队列、模板句或模糊归因。
3. **正式正文**
   - 只有 `published model_story` 计入。
   - A 档经典型号：2000–3500 字。
   - B 档主流型号：1000–1800 字。
   - C 档长尾、入门或资料较少型号：500–900 字。
   - 字数只是最低启发式；主题覆盖和事实审核仍是硬门槛。
4. **正文主题覆盖**
   - 型号身份、产品线位置与重要性。
   - 外形、尺寸、材料与握持。
   - 笔尖、出水或书写表现；第三方体验必须明确归因。
   - 上墨、清洗、维护和适用场景。
   - 版本差异、停产/现售状态和购买时需要确认的事项。
5. **结构化规格**
   - 至少五项公开字段。
   - 品牌、时期/发布年份、笔尖、上墨、材质为核心；尺寸或重量至少一项。
   - 每个字段有独立的 approved citation，不允许一条 row-level citation 解锁整份 spec。
   - 不确定值直接不展示，不能填“随版本变化”“待确认”等占位内容。
6. **来源与证据**
   - 至少两个独立来源组。
   - 至少一个一手来源或同期档案。
   - 至少一个独立二手专业来源。
   - 关键身份、日期、技术结构和规格均有 evidence locator。
7. **版本边界**
   - 已知存在年代、市场、尖号、材料或特别版差异时，必须有版本模块。
   - 基础 spec 只能存放所有版本都稳定成立的事实。
8. **主图**
   - 至少一张确实对应当前型号的 approved primary 图片。
   - 许可、作者、来源、alt 和文件可用性完整。
   - 不使用品牌通用图、错版图或旋转占位图冒充产品图。
9. **无占位块**
   - 公开页不得出现“暂无规格”“暂无来源”“暂无图片”“暂无时间线”等缺口提示。
   - 缺少必需模块时，条目保持 draft，不进入任何公开入口。

Montblanc 149、Parker 51、LAMY 2000、Pilot Custom 823 等标志性型号必须按 A 档处理。

### 5.2 品牌页硬门槛

每个公开品牌页必须同时满足：

- 60–160 字自然中文摘要。
- 一篇 `published brand_story`。
- 说明品牌起源、制造者或公司身份、主要发展节点、代表设计/技术和当前状态。
- 至少一个已经达标并公开的代表型号。
- 至少两个 approved 时间线节点；重要品牌应有更完整的时间线。
- 至少两个独立可靠来源，其中至少一个一手或档案来源。
- 至少一张对应品牌的 approved primary 图；可为品牌标识、厂房、历史广告或有明确品牌归属的代表图。
- 创立年份、产地、所有权和历史节点等事实有 approved claims/citations。
- 不以别名、外部 ID、空时间线或一组型号链接代替品牌介绍。

极小或已消失品牌可以采用 C 档长度，但不能免除身份、来源、正文和代表型号要求。

### 5.3 其他 entity 类型

最终公开视图应覆盖全部 entity 类型，而不是继续依赖 article/concept 黑名单：

- article：有摘要、结构完整正文、合法来源和 import-residue 检查。
- concept/nib/fill/material：有可靠定义、适用边界、来源和真实公开示例。
- 同样必须有 publication status；未达标记录保留在研究库，不进入公开面。

## 6. 来源等级与使用规则

### 6.1 来源等级

| 等级 | 来源 | 可支撑内容 |
| --- | --- | --- |
| A | 厂商官网、手册、同期目录、专利、原始广告/档案 | 产品身份、官方规格、发布、机制、同期事实 |
| B | 专业书、博物馆、钢笔协会、长期专业参考站、作者明确的深度评测 | 历史、版本辨识、技术背景、归因后的体验 |
| C | 信誉稳定零售商、维修资料、论坛和社区讨论 | 当前供货基本信息、补充规格、归因后的经验与问题线索 |
| D | 搜索结果、Marketplace、无作者聚合页、社交摘要 | 仅用于发现线索，不得支撑公开 claim/spec |

官方来源不自动等于所有事实的最高权威。现售营销页可以支撑当前版本信息，但不能自动证明历史版本；独立专业资料可以解释历史和版本，但主观体验必须保持归因。

### 6.2 独立性

- 同一新闻稿、商品文案或资料页的转载和镜像，只算一个来源组。
- 来源独立性以 `independence_group` 判断，而不是只看域名数量。
- 一个零售商的不同地区站点不能被当成两个独立来源。
- 官方产品页和官方新闻稿可以是两个 source items，但如果内容来自同一规格表，只算一个事实来源组。

### 6.3 allowed-use

- `store_full`：在许可允许时可保存和渲染全文。
- `store_excerpt`：只能保存有限摘录并清楚归因。
- `summary_only`：只能用自己的语言概括，不能复制正文。
- `metadata_only`：只能支撑标题、作者、日期、标识等元数据。
- `link_only`：只作为延伸链接，不得支撑 claim/spec。
- `forbidden`：不得进入公开证据链。

现有 `getModelSpec` 和 claim/citation 查询不能只检查 source item 是否 approved，还必须检查 allowed-use 是否允许当前用途。

### 6.4 体验性判断

- “顺滑、偏硬、偏湿、重、握持累、密封好”等不是跨版本的稳定规格。
- 单篇评测只能写成“某作者认为/在某版本上观察到”。
- 写成普遍结论时至少需要两个独立体验来源，并标明适用版本。
- 任何第三方第一人称都不能被改写成本站或用户本人亲测。

## 7. 现售、vintage、地区版本与来源冲突

### 7.1 型号与版本边界

- entity 表示稳定的型号家族身份。
- 年代、地区、材料、尖号、尺寸或特别版差异使用 scoped variant。
- 如果机制、产品身份或市场定位发生根本变化，应拆成独立实体，并建立 predecessor/successor 或 variant-of 关系。
- 现售规格必须记录市场/地区、检索日期和适用版本。
- vintage 规格必须优先使用同期目录、手册、专利、广告扫描或可靠档案，再辅以专业历史资料。
- 当前特别版官网不能反向证明几十年间全部历史版本采用相同笔尖、feed、材料、尺寸或重量。

对 Montblanc 149 这类跨年代型号，current standard、special edition 和 vintage generations 必须分开描述；所有版本共同成立的事实才进入基础型号规格。

### 7.2 价格与在售状态

- 价格不是静态 model spec。
- 公开价格必须带币种、地区、来源和查询日期，并作为 price snapshot 保存。
- 没有日期的“价位段”不得进入核心规格，也不得参与发布门槛。
- “现售/停产”同样需要时间 scope；当前官网下架不能单独证明历史停产年份。

### 7.3 冲突处理

来源冲突按 `entity + predicate + variant/region/date scope` 归组：

1. 相同 scope 出现不同值时，标记为 `unresolved`。
2. 未解决冲突的字段不进入规格卡。
3. 正文如需保留争议，必须明确写出不同说法并分别引用。
4. 不能采用“最新网页覆盖旧资料”的 last-write-wins。
5. 编辑解决冲突时必须保存 resolution note、采用值、采用理由和支撑来源。
6. 存在身份级冲突、实体重复或类型歧义时，整个实体阻止发布。

## 8. 中文自然度与模板化契约

自动检查只能拒绝，不能自动授予语言审核通过。

### 8.1 硬失败模式

- 编辑/后台话术：当前页面、当前档案、后续应、资料不足、研究队列、待核验、待补证、需复核等。
- AI 抽象套话：值得注意的是、此外、综上、总的来说、标志着、见证了、至关重要、持久影响、复杂格局等。
- 模糊归因：很多人认为、行业专家指出、一些批评者认为、多个来源显示等。
- 资料卡模板：型号档案记录了、现有来源包括、日用性可以从这些结构入手、优先按实物图等。
- 机器翻译腔和生硬搭配：过度使用“该、其、具有、提供了、作为……的体现”，英文标点和中文单位混乱。
- 第一人称归属错误：把第三方经历写成本站、编辑或用户亲测。
- 任何 import residue、内部字段名、Research index 或 review status。

### 8.2 全库重复检测

- 20 个汉字以上的完整句在三个以上实体正文重复，进入硬失败清单；明确的版权/归因提示可加入单独白名单。
- 去除品牌、型号、数字和常见功能词后，对正文做 n-gram/SimHash 相似度检查。
- 高相似正文、重复开头、重复结尾和批量“购买时……”段落进入人工复核。
- summary 在条目间必须具有区分度，不能批量套同一模板。
- 正文中的数字、单位、材料、尖号和上墨方式必须与 approved spec/claim 一致。

### 8.3 人工语言审核

内容必须完成独立的 Chinese language review，至少检查：

- 读起来像中文原生资料，而不是逐句英译。
- 句长和节奏有变化。
- 事实、判断和建议边界清楚。
- 不假装本站或用户亲测。
- 没有万能购买建议和同质化结尾。
- 表达直接，不堆“高级感、经典、优秀、值得”等无证据形容词。

现有 importer 中的 `humanizer 45/50` 只是写作者自评，不能替代独立审核状态。

## 9. 媒体契约

公开主图必须同时满足：

- `asset_type = image`。
- `review_status = approved`。
- `usage_status = primary`；gallery 只作为补充。
- 许可在公开允许清单内，作者、来源和 attribution 完整。
- 图片确实对应实体或明确标注的 variant。
- 文件或代理可稳定加载，MIME、大小和安全规则通过。
- alt 能说明图中对象，而不是只有“图片”“钢笔”。
- 不是通用品牌图、商品占位图、旋转占位图或错误型号图。

全库媒体 audit 还必须检查：

- perceptual hash 重复；同图跨实体复用默认进入人工复核。
- 明显白边、截图边框和透明画布；外围高亮/纯白像素比例异常时进入裁切队列。
- 同页重复图片。
- 原图与缩略图是否被误当作两张不同媒体。
- 图片版本与正文/spec 的版本 scope 是否一致。

图片不能为缺少正文、规格或证据的页面提供发布资格。

## 10. 评分模型

评分用于排序补全优先级和衡量成熟度，不取代硬门槛。

| 类别 | 满分 | 硬下限 |
| --- | ---: | ---: |
| 身份与版本 scope | 15 | 12 |
| 可读正文与摘要 | 25 | 20 |
| 结构化事实/品牌时间线 | 20 | 14 |
| 证据链与来源独立性 | 20 | 16 |
| 版本差异与冲突处理 | 10 | 7 |
| 媒体真实性和权利 | 5 | 5 |
| 中文自然度人工审核 | 5 | 5 |

发布需要同时满足：

- 总分至少 80。
- 每个类别达到硬下限。
- 本类型全部必需项存在。
- blocker 数量为零。
- publication status 为 `published`。

A/B/C 是正文深度和研究优先级，不是允许 A 档缺事实、C 档缺来源的质量豁免。

## 11. 最小数据架构与迁移

### 11.1 Migration 1：发布记录与唯一公开视图

新增 `entity_publications`：

```text
entity_id               primary key, references entities
status                  draft | in_review | published | retired
depth_tier              A | B | C
quality_score           integer
reviewed_by             text
reviewed_at             datetime
published_at            datetime
content_hash            text
blockers_json            text
notes                   text
updated_at              datetime
```

新增 `public_entity_readiness` view，基于当前有效关系计算：

- approved/published 数量。
- 有效正文长度和类型。
- 独立来源组数量。
- approved claim/spec/variant/timeline/media 数量。
- 未解决冲突。
- content review 是否仍对应当前 hash。
- 当前类型的硬门槛是否全部满足。

再新增或定义 `public_entities` view，仅包含：

```text
publication.status = published
AND readiness.publishable = 1
AND blockers = 0
```

所有公开查询必须从这一 view 读取，或以 `EXISTS(public_entity_readiness)` 作为统一过滤条件。

### 11.2 Migration 2：逐字段证据与版本 scope

最小新增字段：

- `citations.target_field`：spec citation 必须指向具体字段。
- `model_specs.scope_label`。
- `model_specs.market`。
- `model_specs.valid_from / valid_to`。
- `model_specs.retrieved_at`。
- `model_variants.slug / market / production_start / production_end / status`。
- `claims.variant_id / region / valid_from / valid_to`。
- `claims.conflict_status / resolution_note`。
- `source_registry.source_tier / independence_group`。

如果继续保留一行 `model_specs`，该行只能表示一个清楚标注的 reference/current scope。复杂版本不能继续塞进“随版本变化”文本；后续可演进为 normalized `model_spec_values`。

### 11.3 Migration 3：内容审核记录

新增 `content_reviews`：

```text
id
entity_id
story_id
review_type             fact | language | media | publication
status                  pending | approved | rejected
content_hash
reviewer
notes
reviewed_at
```

summary、story、spec、claim、citation、variant 或 primary media 发生变化后，publication content hash 必须变化；旧审核不能继续使新内容公开。

### 11.4 迁移安全要求

- migration 必须可在本地 SQLite 和远程 Turso 重放。
- 所有新 entity publication 默认 `draft`，禁止默认 published。
- 旧手工黑名单只保留 canonical duplicate/retired identity 语义，不再承担内容门槛。
- 数据补全与 publish 必须是原子操作；新条目不得先进入公开面再慢慢补。

## 12. 页面渲染契约

### 12.1 详情查询

- metadata 与详情页必须查询同一个 `public_entities` 集合。
- 不再先 `SELECT * FROM entities` 再用纯 JS 的 `isPublicEntity()` 判断。
- 详情页、browse、sitemap、entities API、graph、recommendations、by-dimension 和品牌全部型号列表必须共享统一过滤器。

### 12.2 Pen 页面

- pen 也显示 summary，建议增加 `data-testid="entity-summary"`。
- 加载唯一的 `published model_story`，正文容器增加 `data-testid="entity-profile"`。
- ModelArchive 只渲染经过逐字段证据审核的 spec。
- 版本模块读取 approved variants/scoped claims。
- 来源卡区分一手、专业二手、零售和社区，但公开门槛按独立来源组计算。
- 第三方全文/译文与站内编辑正文分区，不能继续混用 `entities.body_md`。

### 12.3 Brand 页面

- brand 显示 summary 和 `published brand_story`。
- 品牌型号列表包含 reverse `made_by` 关系中的全部 `public_entities` 型号，数量和集合双向一致，不做代表性截断。
- 时间线只显示 approved event + approved source。
- 没有时间线、来源、正文或代表型号时不渲染公开占位框，而是阻止整个品牌发布。

### 12.4 失败行为

- 未达标条目不在 sitemap、browse、graph、recommendations、facets 或公开 API 中出现。
- 直接访问未达标 slug 返回 404。
- 如以后需要编辑预览，应使用受保护的 preview route，并返回 noindex；不得复用公开 route。
- 公共页面不显示“暂无……”占位语。可选模块没有内容时直接省略；必需模块没有内容时整条不公开。

## 13. Audit 契约

### 13.1 `audit:entity-quality`

必须改为基于 publication readiness 报告：

- 任何一个 hard blocker 都要报告，不能要求同时有两个问题。
- story、claim、spec、reference、source、variant、timeline、media 全部按有效状态统计。
- 输出每个实体的 blocker codes、得分、depth tier、来源组和公开状态。
- 对所有实体计算；`--limit` 只限制打印条数，不影响失败判断。
- 当前为 published 但存在 blocker 时退出非零。

建议 blocker codes：

```text
missing_summary
missing_published_story
story_below_tier_minimum
missing_required_topics
missing_brand_relation
insufficient_approved_spec_fields
spec_field_without_citation
insufficient_independent_sources
missing_primary_source
missing_secondary_source
unresolved_identity
unresolved_claim_conflict
missing_scoped_variant
missing_primary_media
media_subject_mismatch
language_review_missing
content_hash_stale
template_copy
duplicate_copy
```

### 13.2 `audit:library-coverage`

分成两个明确概念：

- **publication readiness**：只统计能用于公开的 approved/published 数据。
- **backlog inventory**：统计 pending、deprecated、needs_source 和 candidate，用于排期，但不计完成度。

coverage score 不能再把 raw row presence 当作完成。来源按 independence group 去重；model spec 按有 citation 的公开字段计数；媒体按 public media policy 和 subject review 计数。

### 13.3 媒体与语言 audit

- public media audit 继续检查实际文件、代理、安全、MIME、大小和许可。
- 增加重复图、白边/边框、entity mismatch 和 alt 审核。
- 增加 corpus-level Chinese/template audit，并输出所有重复句对和相似条目对。

### 13.4 CI 通过标准

- `published blockers = 0`。
- `public view parity failures = 0`。
- `unresolved public conflicts = 0`。
- `public unsupported spec fields = 0`。
- `public template/duplicate language failures = 0`。
- `public broken/invalid media = 0`。

## 14. 数据层测试契约

为 eligibility 建立完整 fixture matrix：

- 只有 reference、没有 story：失败。
- 只有 story、没有 approved claim/spec：失败。
- deprecated story：失败。
- reviewed 但未 published story：失败。
- pending claim：失败。
- needs_source spec：失败。
- 一条 citation 支撑整份 spec：失败。
- spec 五个字段中一个无 citation：失败。
- 两个镜像来源：只算一个独立来源。
- 只有 retailer/marketplace/search result：失败。
- link_only/metadata_only 被用于技术 claim：失败。
- unresolved conflict：失败。
- 已知 variant 缺 scope：失败。
- 主图许可正确但型号不对应：失败。
- content hash 变化但 review 未更新：失败。
- 所有条件满足：成功。

必须增加集合一致性测试：

```text
detail-public slugs
= browse slugs
= sitemap dynamic entity slugs
= public entities API slugs
= graph/recommendation candidate slugs
= public_entities view slugs
```

任何 surface 多出或少出实体都失败。

## 15. 全量 E2E 契约

对 sitemap 中每个 pen/brand 页面逐条检查，不得抽样：

- HTTP 200、canonical 和 JSON-LD 正确。
- summary 可见，长度达标，内容自然。
- `entity-profile` 正文可见，长度达到 depth tier。
- 必需主题覆盖。
- 规格公开字段数量达标。
- 每个规格字段在数据层有 approved field citation。
- 至少两个独立来源组；一手和二手门槛达标。
- 主图加载正常、alt 有意义、许可和实体匹配。
- 已知版本存在时显示版本模块。
- 页面无“暂无……”和内部编辑状态。
- 页面无 banned patterns、重复模板和第一人称归属问题。
- 移动端无横向溢出，图片无重复和白边异常。

对所有未达标实体逐条检查：

- 不在 sitemap。
- 不在 browse/facets。
- 不在品牌代表型号、graph、recommendations。
- 不在公开 API。
- 直接公开 route 返回 404。

必须新增 Montblanc 149 精确回归测试，至少断言：

- A 档正文完整可见。
- summary 可见。
- 关键规格和逐字段来源存在。
- current/vintage 或 generation 差异清楚。
- 两个以上独立来源组。
- 正确主图。
- 不出现缺省占位语。

删除或修改旧测试中的错误目标：

- 删除“没有规格但保持公开也算通过”的断言。
- 删除 `sitemap >= 550` 的页面数量 KPI。
- 不再用“存在 H1”判定页面不是空 shell。
- 改成 sitemap 与 `public_entities` 精确集合相等。

正式站验收必须使用零重试全量运行；重试只能用于诊断，不得掩盖内容或可用性错误。

## 16. 内容补全与新增实体工作流

每个现有或新增条目都执行同一条流水线：

1. 建立 draft entity 和 canonical identity。
2. 去重、别名和品牌关系审核。
3. 按来源等级搜索，保存 direct URLs、检索日期和 allowed-use。
4. 建立 approved claims，记录 evidence locator 和 scope。
5. 建立逐字段有 citation 的 spec/variant/timeline。
6. 写 summary 和 A/B/C 对应长度的 reader-facing story。
7. 进行事实一致性、来源冲突和版本边界审核。
8. 进行中文自然度与模板重复审核。
9. 进行图片实体、许可、重复和白边审核。
10. 运行 publication readiness audit。
11. 生成 content hash，完成 publication review。
12. 以原子事务切换到 published。

新品牌和型号不得先创建公开壳再补内容。研究阶段记录可以长期保留为 draft，只有完成第 12 步才进入公开面。

## 17. 实施顺序

1. **先止血**：引入 publication status 和唯一 public view；把未达标 pen/brand 从公开面撤下。
2. **修正测量**：改写 entity quality 与 library coverage audit，生成全量、真实 blocker 清单。
3. **修正渲染**：pen/brand 显示 summary 和 published story；去掉公开缺省占位块。
4. **补证据模型**：实施逐字段 citation、source tier/independence、variant scope 和 conflict resolution。
5. **先修用户发现的问题**：按 A 档完成 Montblanc 149，并加入精确回归。
6. **修现有重点条目**：先 A 档经典型号和主要品牌，再 B 档主流型号，最后 C 档长尾。
7. **全量清账**：所有现有 pen/brand 要么 published 且达标，要么 draft/retired 且完全退出公开面。
8. **研究新增目录**：在现有公开边界可信后，再补缺失品牌和型号；每条遵循同一流水线。
9. **三层验收**：本地数据库与构建、远程 Turso 数据审计、正式站全量 E2E 全部通过。
10. **部署后验真**：正式 URL、sitemap、browse、详情、移动端、图片和日志再次全量核对。

## 18. 完成定义

V1.2 只有在以下条件全部成立时才能宣布完成：

- 公开面不存在空壳 pen/brand 页面。
- 任一 published entity 都通过本类型全部硬门槛。
- 所有公开 surface 与 `public_entities` 集合完全一致。
- 全量 publication audit blocker 为零。
- 全量媒体与中文模板审计为零失败。
- 本地和正式站全量 E2E 零重试通过。
- 新增品牌/型号不能绕过 draft → review → published 流程。
- 未达标内容仍可保留在研究数据库，但不会被 sitemap、browse、图谱或直接公开 route 暴露。

最终衡量标准不是数据库里有多少条记录，而是用户打开任何一个公开条目，都能获得一份值得阅读、可以核对、边界诚实的钢笔资料。
