  <name>Task 1: Resolve exact before-state and apply alias, rename, merge and retire</name>
  <files>src/lib/taxonomy/apply-taxonomy.ts, tests/taxonomy/taxonomy-canonical.test.ts</files>
  <behavior>
    - Missing/mismatched source ID/type/slug, duplicate target, alias collision or checksum replay -> dry-run blocker and zero writes.
    - Rename -> same ID, new canonical name/slug, scoped approved alias and redirect ledger; old publication demoted first.
    - Alias -> no new entity/payload copy; normalized tuple is unique and source-item provenance retained.
    - Merge -> survivor retained, compatible set-valued metadata deduped, donor publication retired, lineage/action recorded, donor row/provenance preserved.
    - Retire/gated identity -> publication retired/draft, canonical links removed, no arbitrary successor/brand chosen.
    - Any injected failure -> whole taxonomy transaction rolls back and no applied batch marker remains.
  </behavior>
  <action>
Create a read-only preflight that resolves only manifest IDs, verifies exact before slugs/types, computes the dependency closure and rejects every ambiguity before opening a write transaction. In `applyTaxonomyPlan`, insert an applying batch, then demote all affected current entities and affected canonical brands before changing owners. Implement rename in place without ID changes; insert reviewed scoped aliases separately; merge only manifest-approved compatible attributes/tags/references/external IDs and retain donor history as retired; retire generic/disputed rows without inventing a successor. Record action, lineage and redirect candidate rows with manifest checksum. Use bound SQL and exact cardinality assertions. Never update immutable payload IDs, hard-delete an entity, copy an `entity_content_reviews` row, preserve an approved hash, or flip a target back to published.
